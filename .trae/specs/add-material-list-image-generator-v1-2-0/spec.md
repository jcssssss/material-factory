# V1.2.0 资料列表展示图生成器 Spec

## Why
V1.0/V1.1 已完成「PDF/Word → 小红书素材」的稳定链路，但商品详情页中另一类高频素材——「资料列表展示图」——目前仍需人工打开百度网盘、逐层截图、再拼接调整，存在重复操作多、尺寸不统一、子文件夹需逐个展开等问题。
V1.2.0 需要在不动摇 v1.0/v1.1 输出规格与任务流水线的前提下，新增「读取商品资料文件夹真实结构 → 自动生成白底文件列表展示图」的能力，替代人工网盘截图流程，并支持多商品批量生成。

## What Changes
- 新增 Rust 命令 `scan_folder_tree`：递归扫描商品资料文件夹，返回排除系统文件的目录树结构（含文件名、后缀、层级、类型）
- 新增前端「资料列表展示图」生成器模块：基于 Canvas 渲染白底 1242×1656 px 图片，展示当前目录的直接子项（文件夹优先 + 文件名 + 文件类型图标）
- 新增自动分页能力：当单目录内容超过单张图片承载范围时自动拆分为多张
- 新增多级目录递归生成能力：每个目录生成独立图片，所有图片统一编号输出到商品根目录
- 新增批量处理能力：支持一次选择多个商品文件夹并串行生成
- 新增文件类型图标体系：PDF / Word / Excel / PPT / 文件夹 五类
- 新增「资料列表任务」独立的任务模型与执行器，与现有 PDF 任务流水线并存且互不干扰
- 复用 v1.0/v1.1 的 `ensure_output_dir`、`write_image_file`、`append_log_line` 等基础能力
- **不修改** v1.0/v1.1 的 PDF 任务流水线、状态机、断点恢复逻辑
- **不包含** 百度网盘真实截图、Finder UI 模拟、文件打开效果、动态交互、模板编辑器（V1.20 MVP 限制）

## ADDED Requirements

### Requirement: 商品资料文件夹递归扫描
系统 SHALL 通过 Rust 命令 `scan_folder_tree` 递归扫描商品资料文件夹，返回完整的目录树结构，并自动过滤系统文件。

#### Scenario: 扫描正常的多级目录
- **WHEN** 用户选择商品文件夹 `商品A/`，其下含 `真题资料/2026真题.pdf` 与 `答案.pdf`
- **THEN** 系统返回根目录节点，包含直接子项 `真题资料/`（文件夹）与 `答案.pdf`（PDF 文件）
- **AND** `真题资料/` 节点包含子项 `2026真题.pdf`（PDF 文件）
- **AND** 每个文件节点包含名称、后缀、类型标识；每个文件夹节点包含名称与子节点列表

#### Scenario: 自动忽略系统文件
- **WHEN** 扫描的目录中存在 `.DS_Store`、`Thumbs.db`、`desktop.ini` 等系统文件
- **THEN** 系统在返回的目录树中完全过滤这些文件
- **AND** 不在日志中单独记录每个被忽略的文件，仅记录过滤统计

#### Scenario: 商品根目录名称不展示
- **WHEN** 扫描 `商品A/` 后生成图片
- **THEN** 图片内容不包含 `商品A` 这一名称本身
- **AND** 仅展示 `商品A/` 的直接子项

#### Scenario: 扫描空文件夹
- **WHEN** 扫描到一个不含任何有效子项的文件夹（仅含被过滤的系统文件或完全为空）
- **THEN** 该文件夹节点标记为 `empty: true`
- **AND** 执行阶段不为其生成图片，仅写入一条 warn 日志
- **AND** 继续处理同级其他目录

### Requirement: 资料列表图片渲染规范
系统 SHALL 使用 Canvas 渲染白底 1242×1656 px（3:4）的资料列表展示图片，仅展示当前目录的直接子项，不包含子文件夹内部文件。

#### Scenario: 单目录单张图片
- **WHEN** 某目录的直接子项数量在单张图片承载范围内（默认 ≤ 25 项）
- **THEN** 系统生成一张图片，垂直排列每个子项
- **AND** 每项左侧为文件类型图标，右侧为文件/文件夹名称
- **AND** 背景为纯白色，无商品名称、无文件总数、无营销文案、无水印、无 Logo

#### Scenario: 文件夹优先排序
- **WHEN** 同一目录下既有文件夹又有文件
- **THEN** 图片中文件夹排列在前，文件排列在后
- **AND** 同类内部按名称升序排列（不区分大小写）

#### Scenario: 单目录自动分页
- **WHEN** 某目录的直接子项数量超过单张图片承载范围
- **THEN** 系统自动拆分为多张图片
- **AND** 每张图片项数 ≤ 单张承载上限
- **AND** 子项顺序按排序结果连续分配到各张图片

#### Scenario: 文件类型图标映射
- **WHEN** 渲染文件项时
- **THEN** `.pdf` 显示 PDF 图标，`.docx`/`.doc` 显示 Word 图标，`.xlsx`/`.xls` 显示 Excel 图标，`.pptx`/`.ppt` 显示 PPT 图标
- **AND** 未识别后缀的文件显示通用文件图标
- **AND** 文件夹项显示文件夹图标

### Requirement: 多级目录递归生成与统一编号
系统 SHALL 对商品资料文件夹下的每个目录（含根目录与所有非空子目录）独立生成图片，所有图片统一编号输出到商品根目录。

#### Scenario: 深度优先递归生成
- **WHEN** 商品文件夹下含多级子目录
- **THEN** 系统按深度优先顺序依次为每个非空目录生成图片
- **AND** 单目录若分页则先输出该目录的全部分页图片，再递归进入下一目录

#### Scenario: 统一编号输出
- **WHEN** 一个商品的所有目录图片生成完毕
- **THEN** 所有图片以 `资料列表_01.jpg`、`资料列表_02.jpg`、… 形式保存到商品根目录
- **AND** 编号在商品范围内全局递增、两位零填充
- **AND** 若图片总数 ≥ 99，编号自动升级为三位零填充（如 `资料列表_100.jpg`）

#### Scenario: 输出目录与现有素材并存
- **WHEN** 商品根目录已存在 `主图/`、`详情图/`、`笔记图1/` 等子目录
- **THEN** 系统将 `资料列表_NN.jpg` 直接写入商品根目录，不破坏已有子目录
- **AND** 若同名文件已存在则直接覆盖

### Requirement: 批量商品处理
系统 SHALL 支持一次选择多个商品文件夹并串行生成资料列表图片，单商品失败不影响后续商品。

#### Scenario: 批量选择商品文件夹
- **WHEN** 用户一次选择多个商品文件夹（或一个包含多个商品子目录的父文件夹）
- **THEN** 系统按顺序对每个商品文件夹独立执行扫描与生成流程
- **AND** 每个商品的图片编号独立计算，从 `01` 开始

#### Scenario: 单商品失败隔离
- **WHEN** 某商品在扫描或生成阶段抛出异常
- **THEN** 系统记录该商品的失败原因并标记为失败
- **AND** 继续处理队列中下一个商品
- **AND** 不影响其他商品已生成的图片

#### Scenario: 批量执行结果汇总
- **WHEN** 批量任务执行完毕
- **THEN** 系统返回每个商品的成功/失败状态与生成图片数量
- **AND** 失败商品在结果中包含失败原因

### Requirement: 资料列表任务模型与执行器
系统 SHALL 提供独立的「资料列表任务」模型与执行器，与 v1.0/v1.1 的 PDF 任务流水线并存，互不干扰。

#### Scenario: 创建资料列表任务
- **WHEN** 用户在「资料列表生成器」页面选择一个或多个商品文件夹并点击「加入队列」
- **THEN** 系统创建一个资料列表任务，包含任务名、商品文件夹列表、创建时间
- **AND** 任务初始状态为 `pending`

#### Scenario: 串行执行队列
- **WHEN** 用户点击「启动队列」
- **THEN** 系统按入队顺序串行执行每个任务
- **AND** 单任务内按商品文件夹顺序串行处理

#### Scenario: 任务状态展示
- **WHEN** 任务执行过程中
- **THEN** 进度面板展示当前任务名、当前商品名、已生成图片数、总进度
- **AND** 队列表格展示每个任务的状态（待执行/执行中/已完成/失败）

#### Scenario: 任务历史持久化
- **WHEN** 任务执行完毕或失败
- **THEN** 任务记录保存到 localStorage `xhs-pic:material-list-history`，最多保留 200 条
- **AND** 不与 PDF 任务历史 `xhs-pic:history` 混淆

### Requirement: 文件读取异常处理
系统 SHALL 在扫描与生成阶段对异常文件进行隔离处理，不中断整体流程。

#### Scenario: 单文件读取失败
- **WHEN** 扫描阶段某个文件因权限或 IO 错误无法读取元数据
- **THEN** 系统跳过该文件
- **AND** 记录 warn 日志，包含文件路径与错误原因
- **AND** 继续扫描同目录其他文件

#### Scenario: 图片渲染失败
- **WHEN** 某个目录在 Canvas 渲染阶段抛出异常
- **THEN** 系统跳过该目录的图片生成
- **AND** 记录 error 日志，包含目录路径与错误原因
- **AND** 继续处理下一个目录，不影响统一编号的连续性（跳过编号不复用）

### Requirement: 资料列表生成器页面
系统 SHALL 在桌面应用中新增「资料列表生成器」导航入口与独立页面，与现有「工作台」「历史记录」「日志」页面并列。

#### Scenario: 导航入口
- **WHEN** 用户打开应用
- **THEN** 顶部导航栏新增「资料列表」Tab，与「工作台」「历史记录」「日志」并列
- **AND** 点击「资料列表」进入资料列表生成器页面

#### Scenario: 任务表单
- **WHEN** 用户在资料列表页面创建任务
- **THEN** 表单提供任务名输入、商品文件夹选择（支持多选）、加入队列按钮
- **AND** 表单不展示页码规则、输出目录等 PDF 任务专用字段（输出固定为商品根目录）

#### Scenario: 队列与进度
- **WHEN** 任务加入队列后
- **THEN** 页面展示队列表格（任务名、商品数、状态、操作）与进度面板
- **AND** 提供「启动队列」按钮启动串行执行

#### Scenario: 产品需求文档同步

- **THEN** `产品需求文档-小红书素材工厂.md` 新增「资料列表展示图生成器」功能模块章节
- **AND** 章节覆盖功能背景、用户价值、输入输出规则、图片规范（1242×1656 白底）、批量与异常处理、MVP 限制
- **AND** 在产品概述章节同步「新增资料列表生成器」
- **AND** 在非目标章节同步「不包含模板编辑器与网盘真实截图」

- **THEN** `技术架构文档-小红书素材工厂.md` 版本号升级到 v1.2.0
