# 桌面批量 PDF 转小红书素材 Spec

## Why
当前项目的有效蓝图已经切换为“完全本地执行的桌面 PDF 批处理工具”，核心目标是按商品任务批量处理 PDF，并稳定导出适合小红书使用的图片素材。
需要把执行规格明确到任务模型、页码规则、输出结构、失败处理和本地持久化层面，作为后续 `Tauri + React + TypeScript` 实现的统一约束。

## What Changes
- 新增完全本地桌面应用形态，替代此前偏 Web 的概念方向
- 新增“一个任务对应一个商品目录”的任务模型
- 新增任务输入模式，支持单个 PDF、多个 PDF、或扫描一个包含多个 PDF 的文件夹
- 新增串行任务队列，支持任务自动续跑且失败不中断后续项
- 新增页码规则，支持“前 N 页”和“自定义页码/页码范围”并合并去重执行
- 新增固定导出规格，统一输出 `3:4` 竖版、`JPG 质量 100%`、目标 `300 DPI`
- 新增本地持久化，保存最近任务、执行状态、输出目录和错误日志
- 明确首版不包含 Word、云端同步、模板编辑器、多尺寸导出和并发任务执行

## Impact
- Affected specs: 桌面工作台、任务队列、本地 PDF 处理、图片导出、日志与历史记录
- Affected code: `src-tauri`、`src/pages`、`src/components/task`、`src/lib`、`src/store`

## ADDED Requirements

### Requirement: 桌面工作台与任务模型
系统 SHALL 提供完全本地执行的桌面工作台，并以“一个任务对应一个商品”的模型组织批处理输入与输出。

#### Scenario: 创建商品任务
- **WHEN** 用户在工作台中创建一个任务并填写任务名
- **THEN** 系统创建一个待执行任务，并将该任务视为一个独立商品处理单元

#### Scenario: 任务输入支持多种 PDF 来源
- **WHEN** 用户为一个任务选择单个 PDF、多个 PDF，或一个包含多个 PDF 的文件夹
- **THEN** 系统保存输入路径，并生成该任务的 PDF 输入集合

#### Scenario: 文件夹中无 PDF
- **WHEN** 用户选择的文件夹中没有任何 PDF
- **THEN** 系统阻止任务开始执行，并提示当前输入无可处理文件

### Requirement: 首版仅支持 PDF
首版系统 SHALL 仅支持 PDF 作为实际处理输入，不要求在当前版本支持 Word 或其他文档格式直接导出。

#### Scenario: 用户选择非 PDF 文件
- **WHEN** 用户尝试将非 PDF 文件作为处理输入
- **THEN** 系统阻止其进入执行流程，并提示当前版本仅支持 PDF

### Requirement: 页码规则解析
系统 SHALL 支持“前 N 页”和“自定义页码/页码范围”两类规则，并在执行前完成解析、合并、去重、升序和合法性校验。

#### Scenario: 使用前 N 页
- **WHEN** 用户设置导出前 N 页
- **THEN** 系统选择每个 PDF 的前 N 个合法页码作为候选集合

#### Scenario: 使用自定义页码
- **WHEN** 用户输入 `1,3,5-8` 形式的页码规则
- **THEN** 系统解析为去重且升序的合法页码集合

#### Scenario: 同时配置两类规则
- **WHEN** 用户同时填写前 N 页和自定义页码
- **THEN** 系统合并两类规则后去重，并以最终合法页码集合执行

#### Scenario: 页码部分超出范围
- **WHEN** 用户输入的部分页码超过 PDF 总页数
- **THEN** 系统忽略非法页码并记录警告日志

#### Scenario: 页码输入非法
- **WHEN** 用户输入无法解析的页码表达式
- **THEN** 系统阻止任务开始，并在表单区提示错误

### Requirement: 串行任务队列
系统 SHALL 以串行方式执行任务队列，一个任务结束后自动开始下一个任务。

#### Scenario: 正常串行执行
- **WHEN** 用户启动包含多个任务的队列
- **THEN** 系统按任务顺序依次执行，且无需用户逐个手动启动

#### Scenario: 单任务失败不中断队列
- **WHEN** 某个任务执行失败
- **THEN** 系统记录失败原因，并继续执行后续任务

### Requirement: PDF 逐页处理与失败续跑
系统 SHALL 按“1 页 PDF 转 1 张图片”的规则处理 PDF，并在页级和 PDF 级错误发生时继续处理后续工作项。

#### Scenario: 导出单页图片
- **WHEN** 系统处理某个 PDF 的某一合法页
- **THEN** 系统生成该页对应的一张图片文件

#### Scenario: 单页失败继续下一页
- **WHEN** 某一页渲染或保存失败
- **THEN** 系统记录该页错误信息并继续处理下一页

#### Scenario: 单个 PDF 失败继续同任务其他 PDF
- **WHEN** 一个任务中的某个 PDF 解析失败或无法导出
- **THEN** 系统记录该 PDF 的失败信息，并继续处理该任务中的其他 PDF

### Requirement: 固定输出规格与目录命名
系统 SHALL 将导出图片统一生成为固定 `3:4` 竖版 JPG，质量 `100%`，目标 `300 DPI`，并按照任务目录和 PDF 来源组织输出。

#### Scenario: 页面比例不匹配
- **WHEN** PDF 页面比例与 `3:4` 目标画布不一致
- **THEN** 系统采用等比缩放、居中放置和背景补边方式输出，且不裁切原始页面主体内容

#### Scenario: 输出到任务目录
- **WHEN** 一个任务执行导出
- **THEN** 系统将图片写入 `输出根目录/{任务名或商品名}/`

#### Scenario: 任务内包含多个 PDF
- **WHEN** 一个任务包含多个 PDF
- **THEN** 系统按 `输出根目录/{任务名}/{PDF 文件名}/` 组织文件，并保证同任务内不同 PDF 的导出结果互不混淆

#### Scenario: 图片命名稳定可追踪
- **WHEN** 系统输出某个 PDF 页的图片文件
- **THEN** 系统使用稳定命名规则，例如 `{pdfBaseName}_p{页码三位}.jpg`

### Requirement: 本地持久化与日志
系统 SHALL 完全在本地保存最近任务、任务输入参数、输出目录、执行状态、应用级日志和任务级错误日志。

#### Scenario: 查看最近任务
- **WHEN** 用户打开历史任务或最近任务页面
- **THEN** 系统展示最近任务摘要、状态和输出目录

#### Scenario: 查看执行日志
- **WHEN** 用户打开日志查看入口
- **THEN** 系统展示应用运行日志、任务执行日志和错误日志

#### Scenario: 应用重启后查看历史
- **WHEN** 用户关闭应用后再次打开
- **THEN** 系统保留最近任务元数据和日志，但不自动恢复未完成执行

## MODIFIED Requirements

### Requirement: 首版能力边界
首版系统 SHALL 聚焦“稳定批处理 + 正确导出 + 清晰日志”，不要求在当前版本支持云端同步、账号系统、模板编辑器、多尺寸导出或并发任务执行。

#### Scenario: 用户期望并发执行多个任务
- **WHEN** 用户在首版中加入多个任务
- **THEN** 系统仍按串行队列执行，而非并发执行

## REMOVED Requirements

### Requirement: 通用 Web 服务式素材生成
**Reason**: 当前目标已明确为完全本地执行的桌面批处理工具，不再以 Web 服务/API 为首版核心形态。
**Migration**: 将原有概念性 Web 架构调整为 `Tauri + React` 本地架构，后续若需云端能力可在桌面版稳定后增补规格。
