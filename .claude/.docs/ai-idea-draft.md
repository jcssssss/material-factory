# 需求理解与分析

## 业务场景

用户经营的是**小红书虚拟资料电商**——销售各类考试的历年真题及答案解析。核心操作流程是：**选品 → 整理资料 → 做商品图 → 上架商品 → 做笔记图 → 发布笔记**。其中，**选品**和**笔记**是生意的两个核心杠杆。

## 当前痛点

用户每天投入 8-10 小时，其中大量时间花在**纯手工、重复性**的图片制作上，具体包括：

| 环节 | 当前做法 | 工具 |
|------|---------|------|
| 去水印/页眉页脚 | 手动用 PDFgear 或夸克网盘涂改液 | 多个外部工具切换 |
| 资料预览截图 | 百度网盘预览 + 微信截图 | 手动截图 |
| 商品主图 | 稿定设计画板中手动排版文字+背景+截图 | 稿定设计 |
| 资料详情图 | 稿定设计中逐张缩放、居中/对齐 | 稿定设计 |
| 仿打印实拍图 | 手机拍照 → photopea 正片叠底合成 | 手机+photopea |

## 期望目标

**输入资料文件（PDF/Word）→ 一键自动生成所有需要的图片**，包括：

1. 商品主图（3:4 或 1:1，背景+文字+缩略截图+阴影）
2. 资料内容预览图（3:4，居中展示）
3. 资料列表图（3:4，左对齐）
4. 仿打印实拍图（拍照背景 + multiply 合成）

## 分析看法

### 1. 这个 PRD 更像是一份"业务流程说明书"而非产品需求文档

它完整描述了用户怎么做生意的（从选品到发布笔记的全链路），但作为开发需求文档，有几个关键信息缺失：

- 输入输出规格的精确描述（例如"去水印"具体支持哪些类型的水印？彩色水印还是文字水印？）
- 交互流程和 UI 设计（用户怎么配置主图的文字内容、背景？）
- 优先级排序（哪些功能先做、哪些后做？）

### 2. 核心需求的层次应该分层

建议将需求拆成三个层次：

**Layer 1（当前应聚焦）：现有能力的完善与串联**
- 已有 PDF 渲染、3:4 输出、打印合成、列表图生成，这些能力可能已经可以覆盖用户 60-70% 的工作量
- 关键是**体验打磨**和**流程串联**，让"输入 PDF → 输出全套图"这个核心链路顺畅

**Layer 2（近期补充）：去水印 + 主图生成**
- 去水印/页眉页脚（技术上可分两种：页眉页脚区域裁剪，水印检测与去除）
- 主图生成（背景模板 + 文字叠加 + 缩略预览图 + 阴影效果）——这本质是一个"画布排版引擎"

**Layer 3（远期）：发布自动化 + AI + 数据分析**
- 商品上架、笔记发布的自动化（涉及小红书/电商平台的接口或 RPA）
- AI 选品、AI 生成笔记文案——这是完全不同的产品形态

### 3. 技术可行性和风险

- **去水印**是这个需求中最"模糊"也最"技术不确定"的部分。水印类型千差万别（居中半透明大字、角落彩色 logo、平铺文字），没有一种通用方案可以完美去除所有水印。建议限定范围：先做页眉页脚区域裁剪（简单可靠），再做常见的半透明居中水印检测与去除（需要图像处理算法，有失败概率）。
- **1:1 尺寸**是纯参数变化，成本极低。
- **主图排版引擎**的工作量取决于灵活度需求——如果用户接受"选模板+填文字"的固定布局，会简单很多；如果要求自由排版，那就是一个微型设计工具，复杂度大幅上升。

### 4. 建议的路径

当前最务实的做法是：**先把已有的 PDF→图片→列表图→打印图这条链路的产品体验做好**，让用户真正能用起来、看到效率提升，然后逐步迭代去水印、主图排版等功能。而不是试图一次性覆盖 PRD 中的所有远期规划。
